「絵」を見せれば AI がそれをコードにしてくれたら超ラク。 でもAIは絵を直接見ることができないので、誰かが絵を AI に渡してあげる必要がある。 その「渡し役」のことを MCP（Model Context Protocol） といいます。

⚠️ Figma が用意してる「公式」のやり方

普通に使うとこうなる。でもこれだと困る理由があります。

⚠ いまのデフォルト：公式 MCP の流れ
1
🤖AI（Copilot）
「この Figma の絵をコードにして〜」と頼まれる。
絵を取ってくる必要があるので、郵便屋さん（公式 MCP）に「絵ちょうだい」と頼む。
2
📮公式 MCP（郵便屋さん）
Figma に「あの絵を画像にして！」と注文する。
3
🎨Figma
絵を画像（PNG）に変換する。
そして…… 変換した画像を「公開ロッカー」に置いてしまう。
⚠ Figma の仕組み的に、この処理はインターネット上の公開された AWS S3 バケットに保存される
4
📦公開ロッカー（AWS S3）
「ロッカー番号（URL）はこれです」と教えてくれる。
でもこのロッカー、カギがないので誰でも開けられる。
5
🤖AI（Copilot）
そのロッカー番号（URL）を使って画像を見て、コードを書いてくれる。
めでたしめでたし……と思いきや。
😱
会社の秘密のデザインが、ネット上の「カギなしロッカー」に置かれてしまう！ URL を知っている人なら誰でも見られる状態。会社のルール的にアウト。だから会社では使えない。
4

✨ 自分たちで作った「自作」のやり方

外部のロッカーもサーバーも一切使わず、全部「自分の作業部屋（Codespaces）」の中で完結させました。

✓ 自作 MCP の流れ（全部 Codespaces 内）
1
🤖AI（Copilot）
「この絵をコードにして〜」と頼まれる。
同じ作業部屋にいる自作 MCPに「絵ちょうだい」と頼む。
✓ ネット越しじゃない。同じ Codespace の中だけで会話している
2
📮自作 MCP
Figma の API（公開ロッカーに置く仕組み）は使わない。
かわりに、ロボット撮影係を呼ぶ。
3
🎭ロボット撮影係（Playwright）
普通の人と同じように Figma をブラウザで開いて、自分でスクリーンショットを撮る。
✓ 画像はそのまま作業部屋（Codespaces）のメモリの中にいる
4
📮自作 MCP
画像を AI に渡すときは、URL じゃなくて画像そのものを直接渡す。
（base64 という形式で、画像のデータをまるごと送る）
✓ そもそも公開できる URL を一切作らない
5
🤖AI（Copilot）
渡された画像を見てコードを書いてくれる。
めでたしめでたし、今度は本当に。
🎉
画像が Codespaces の外を一切出ない！外部のロッカーもサーバーも経由しない。 そもそも外向きの URL を作らないので、漏れる先がない。社内ルール的にも OK。
5

一言でいうと

だから外に何も出ない。だから会社でも使える。
