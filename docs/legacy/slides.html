🚨
Figma 公式 MCP は /v1/images を呼び出し、生成された PNG URL が figma-alpha-api.s3.us-west-2.amazonaws.com（公開 AWS S3）に乗る。
社外クラウドへの設計データ流出 → データガバナンス違反
🔓 無認証アクセス可能
presigned URL は期限内なら誰でもアクセス可
📋 監査ログなし
誰がいつどのデザインを取得したか追跡不可
🏢 自社管理外
Figma Inc. のインフラ上にデータが滞留
Solution

提案するアプローチ

✗ 公式 MCP（従来）
Figma REST /v1/images 経由で PNG URL を生成
画像が公開 S3 に配置される
署名付き URL を Copilot に渡す → 外部 URL として記録
監査証跡なし・データ保持期間不明
✓ figma-mcp-poc（本 PoC）
Playwright が Figma Web を直接レンダリング
PNG バイト → Supabase Storage（自社管理・非公開）
MCP レスポンスは base64 PNG インライン（URL なし）
全操作を audit_log テーブルに記録
🔒
ガバナンス保証： /v1/images を一切呼び出さず、設計データは自社 Supabase プロジェクト内のみに存在。 MCP ツールは公開 URL を生成しない。

Security

セキュリティ設計

✓ /v1/images の呼び出しなし確認済み  —  grep -rn "/v1/images" packages/ → 0 件
✓
Per-user データ分離 (RLS)
全 Supabase クエリに created_by = userId を明示。RLS ポリシーでダブルチェック。ユーザー A が B のアセットを参照不可。
✓
2 種類の認証方式
短寿命 JWT（Supabase 発行・1h）と長寿命 fmps_ API キー（SHA256 ハッシュ保存）の両対応。
✓
公開 URL ゼロ
MCP ツールは PNG バイトを base64 インラインで返す。presigned URL の発行ルートは MCP 経路に存在しない。
✓
Rate Limiting
IP ごとに認証失敗 60 回/分の上限。スライディングウィンドウでブルートフォース攻撃を防御。
✓
全操作の監査ログ
audit_log テーブルに actor / event / asset_id / meta を記録。誰がいつ何をレンダリングしたか追跡可能。
✓
分類タグ
アセットに classification（internal / confidential）と tier（A/B/C）を付与。将来的なアクセスポリシー差別化に対応。
